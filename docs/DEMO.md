# Three-minute demo — recording plan

Record only working features built during the hackathon. Use your own desk photos. Avoid showing the API dashboard, keys, email, private tabs or notifications. Record at 1080p if available. English narration is suggested for judges; Spanish UI is also supported.

## Before recording

Take a clear BEFORE photo of your messy desk. Use the same position for the real AFTER photo. Include the cables or other friction visibly. Avoid documents, faces and private screens. Run the whole workflow once. Save a PNG and JSON as backup evidence. If an inference segment is sped up or cut, label the edit and retain the model receipt. Never present a stored or generated image as live real-world completion.

## 0:00–0:20 — the hook

“Software gets patches. The real world usually gets a to-do list we never finish. PATCH IRL turns a photo of everyday friction into one practical change you can actually make. I built this during the hackathon, starting with the space I know best: my own desk.”

Show your actual messy desk, then the app.

## 0:20–0:45 — constraints make it useful

Upload the BEFORE photo. Enter: “These cables fall behind the desk and get in the way. I rent, so no drilling. Use what I already have.” Select Use what I have.

“This is not a dream-room generator. My budget, my belongings and my rental constraints shape the patch.”

## 0:45–1:20 — show real Meta reasoning output

Click Find my patch. Show the resulting observations, uncertainty, materials, actions and markers. Open the model receipt briefly.

“Muse Spark reads the actual photo and returns a structured intervention. Each action connects back to a region in my space. It tells me what it can see, what it cannot know, and what observable check would count as progress.”

Use the actual plan's actions in narration. Do not recite imagined results.

## 1:20–1:50 — visualize, with an honest boundary

Click Visualize this patch; move the before/concept slider.

“Muse Image edits the original scene to help me see the intended change. This is labeled as an AI concept. It is not proof that anything has been repaired.”

If Muse Image actually fails: show the real error and action map, say “Image generation was unavailable for this run. The Spark-backed action map still gives me a usable, exportable patch.” Do not claim use of Muse Image succeeded if it did not.

## 1:50–2:25 — close the physical loop

Show a short shot of actually organizing the cables according to safe, sensible actions in the plan. Check off actions in the app, then upload the ACTUAL AFTER photo.

“A render is not impact. After applying the patch, I upload a real photo. Muse Spark compares visible changes against the same plan, and can return improved, partial or unclear.”

Show the actual assessment. If it is partial or unclear, state that honestly.

## 2:25–2:45 — export

Export PNG; show the downloaded reality patch. Briefly show the JSON includes model receipts.

“The output is a reality patch I can take with me: the original, the proposal or action map, the steps and a check. Model receipts make the inference traceable.”

## 2:45–3:00 — close

“Built for Your World means starting with the world right in front of you. PATCH IRL uses Meta's models to move from seeing a problem to planning, making and checking one achievable improvement. Small fixes. Real life.”

Show the public repo URL and project name. End at or below 3:00. Review the exported video and test its public link in a signed-out browser before submission.
